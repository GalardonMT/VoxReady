# PLAN DE IMPLEMENTACIÓN: DISPARO HTTP INTERNO, ESCALADO A CERO Y PIPELINE DEL WORKER (ENTORNOS EXPRESS)

Este plan de implementación define las especificaciones técnicas, modificaciones de código y comandos de infraestructura para adaptar la arquitectura de VoxReady a las restricciones de los entornos Express de Azure Container Apps (donde los disparadores KEDA de Service Bus no están soportados), garantizando el autoescalado estricto de 0 a 1 réplica mediante tráfico HTTP privado y la integración de marcas de tiempo (`turns`).

---

### ARQUITECTURA DE COMUNICACIÓN PRIVADA

Dado que el entorno Express solo admite escalado por HTTP, CPU y Memoria, se sustituye el desacoplamiento por Service Bus por una invocación HTTP interna directa:

```text
[ Frontend ]
     │
     │ 1. POST /v1/sessions/{id}/finish { blobPath, turns }[cite: 5, 6]
     ▼
[ ca-backend-api ]
     │
     ├─► 2. Registra fin de sesión en Azure SQL (status = 'analyzing')[cite: 5, 7]
     │
     └─► 3. POST http://ca-analysis-worker/analyze (DNS privado interno en ACA)
              │
              ▼ (Azure despierta el worker de 0 a 1 réplica automáticamente)
[ ca-analysis-worker ]
     │
     ├─► 4. Responde 202 Accepted de inmediato al backend[cite: 5]
     ├─► 5. Ejecuta pipeline en BackgroundTasks (FFmpeg, Parakeet, MediaPipe, Llama)[cite: 2]
     ├─► 6. Persiste reporte consolidado en Azure SQL (status = 'completed')[cite: 2, 7]
     │
     ▼ (Al terminar y expirar el tiempo de inactividad, ACA escala a 0 réplicas)

```

### MÓDULO 1: ACTUALIZACIÓN DEL BACKEND (`ca-backend-api`)

El backend debe recibir los `turns` en el endpoint de finalización, registrar el inicio del análisis en base de datos y despachar la solicitud HTTP interna hacia el worker.

#### 1.1 Modelo de Datos Pydantic (`schemas/session.py`)

Actualizar los esquemas de petición para aceptar la lista opcional de intervalos de tiempo:

```python
from typing import List, Optional
from pydantic import BaseModel, Field

class TurnInterval(BaseModel):
    questionId: str
    sequenceNo: int
    startMs: int
    endMs: int

class FinishSessionRequest(BaseModel):
    blobPath: str = Field(..., description="Ruta relativa del archivo WebM en el storage")
    turns: Optional[List[TurnInterval]] = Field(default=[], description="Segmentación temporal por pregunta")

class WorkerTriggerPayload(BaseModel):
    sessionId: str
    jobId: str
    rubricVersionId: str
    blobPath: str
    turns: List[TurnInterval]

```

#### 1.2 Cliente HTTP Interno para el Worker (`services/worker_client.py`)

Crear un cliente asíncrono basado en `httpx` para invocar al worker mediante su FQDN privado:

```python
import logging
import httpx
from schemas.session import WorkerTriggerPayload

logger = logging.getLogger(__name__)

WORKER_INTERNAL_URL = "http://ca-analysis-worker/analyze"

async def trigger_worker_analysis(payload: WorkerTriggerPayload) -> bool:
    """
    Envía la señal de inicio de análisis al worker mediante HTTP interno.
    La llamada despertará el contenedor de 0 a 1 réplica.
    """
    try:
        async with httpx.AsyncClient(timeout=10.0) as client:
            response = await client.post(
                WORKER_INTERNAL_URL,
                json=payload.model_dump(),
                headers={"Content-Type": "application/json"}
            )
            if response.status_code == 202:
                logger.info(f"Worker activado exitosamente para la sesión {payload.sessionId}")
                return True
            else:
                logger.error(f"Worker respondió con estado inesperado {response.status_code}: {response.text}")
                return False
    except httpx.RequestError as exc:
        logger.error(f"Error de red contactando al worker interno: {str(exc)}")
        return False

```

#### 1.3 Endpoint `POST /v1/sessions/{sessionId}/finish` (`routers/sessions.py`)

Reemplazar la publicación en Azure Service Bus por el despacho directo al worker:

```python
import uuid
from fastapi import APIRouter, Depends, HTTPException, status
from schemas.session import FinishSessionRequest, WorkerTriggerPayload
from services.worker_client import trigger_worker_analysis
from db.connection import get_db_cursor

router = APIRouter(prefix="/v1/sessions", tags=["Sessions"])

@router.post("/{sessionId}/finish", status_code=status.HTTP_202_ACCEPTED)
async def finish_session(
    sessionId: str,
    payload: FinishSessionRequest,
    cursor = Depends(get_db_cursor)
):
    # 1. Validar que la sesión exista y esté en estado compatible
    cursor.execute("SELECT id, status, rubric_version_id FROM session WHERE id = ?", sessionId)
    session = cursor.fetchone()
    if not session:
        raise HTTPException(status_code=404, detail="Sesión no encontrada")
    
    # 2. Generar registro de analysis_job
    job_id = str(uuid.uuid4())
    cursor.execute("""
        INSERT INTO analysis_job (id, session_id, rubric_version_id, status, started_at, created_at, updated_at)
        VALUES (?, ?, ?, 'running', SYSUTCDATETIME(), SYSUTCDATETIME(), SYSUTCDATETIME())
    """, (job_id, sessionId, session.rubric_version_id))

    # 3. Transicionar estado de la sesión
    cursor.execute("""
        UPDATE session 
        SET status = 'analyzing', finished_at = SYSUTCDATETIME(), updated_at = SYSUTCDATETIME()
        WHERE id = ?
    """, sessionId)
    cursor.commit()

    # 4. Despachar llamada HTTP interna al worker
    trigger_payload = WorkerTriggerPayload(
        sessionId=sessionId,
        jobId=job_id,
        rubricVersionId=str(session.rubric_version_id),
        blobPath=payload.blobPath,
        turns=payload.turns or []
    )
    
    worker_started = await trigger_worker_analysis(trigger_payload)
    if not worker_started:
        logger.warning(f"No se pudo confirmar el inicio del worker para job {job_id}. Reintentar vía polling.")

    return {
        "sessionId": sessionId,
        "status": "analyzing",
        "analysisId": job_id,
        "estimatedSeconds": 45
    }

```

### MÓDULO 2: TRANSFORMACIÓN DEL WORKER A SERVIDOR FASTAPI (`ca-analysis-worker`)

El worker deja de ser un script en bucle continuo y se transforma en un servicio FastAPI que expone un endpoint HTTP interno en el puerto 8000 con `BackgroundTasks`.

#### 2.2 Servidor Principal (`main.py`)

Implementar la interfaz HTTP requerida para el autoescalado de ACA:

```python
import logging
from fastapi import FastAPI, BackgroundTasks, status
from pydantic import BaseModel
from typing import List, Optional
from core.pipeline_orchestrator import process_session_pipeline

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger("analysis-worker")

app = FastAPI(title="ca-analysis-worker", version="2.0.0")

class TurnInterval(BaseModel):
    questionId: str
    sequenceNo: int
    startMs: int
    endMs: int

class JobRequest(BaseModel):
    sessionId: str
    jobId: str
    rubricVersionId: str
    blobPath: str
    turns: Optional[List[TurnInterval]] = []

@app.get("/health")
def health_check():
    return {"status": "ok", "service": "ca-analysis-worker"}

@app.post("/analyze", status_code=status.HTTP_202_ACCEPTED)
async def trigger_analysis(job: JobRequest, background_tasks: BackgroundTasks):
    """
    Recibe la orden de trabajo, responde 202 de inmediato para liberar al backend
    y procesa la inferencia multimodal en segundo plano.
    """
    logger.info(f"Trabajo recibido para sesión {job.sessionId} (Job: {job.jobId})")
    
    # Delegar la ejecución pesada para no bloquear la conexión HTTP
    background_tasks.add_task(
        process_session_pipeline,
        session_id=job.sessionId,
        job_id=job.jobId,
        rubric_version_id=job.rubricVersionId,
        blob_path=job.blobPath,
        turns=[t.model_dump() for t in job.turns]
    )
    
    return {"status": "accepted", "sessionId": job.sessionId, "jobId": job.jobId}

```

#### 2.3 Orquestador de Pipeline con Filtro de Turnos (`core/pipeline_orchestrator.py`)

Asegurar que el orquestador divida los análisis usando los `turns` recibidos:

```python
import os
import logging
import pyodbc
from core.audio_analyzer import extract_and_analyze_audio
from core.vision_client import send_frames_to_vision_service
from core.llm_judge import evaluate_turns_content
from core.report_builder import build_consolidated_report
from core.narrative_generator import generate_visum_report

logger = logging.getLogger(__name__)

def process_session_pipeline(session_id: str, job_id: str, rubric_version_id: str, blob_path: str, turns: list):
    db_conn = pyodbc.connect(os.environ["SQL_CONNECTION_STRING"])
    cursor = db_conn.cursor()
    
    try:
        logger.info(f"Iniciando pipeline multimodal para sesión {session_id}")
        
        # 1. Descargar video desde Azure Blob Storage con SAS interna
        local_video_path = f"/tmp/{session_id}.webm"
        # download_blob(blob_path, local_video_path)

        # 2. Análisis de Voz (NVIDIA Parakeet + Métricas locales en Python)
        # Retorna transcript completo, word_offsets y métricas de fluidez
        voice_results = extract_and_analyze_audio(local_video_path, turns)

        # 3. Análisis de Imagen (Muestreo a 0.5 FPS y envío a ca-vision-service)
        vision_results = send_frames_to_vision_service(local_video_path, turns)

        # 4. Evaluación de Contenido por Turno (LLM Juez con escala 1-5 de Visum)
        content_results = evaluate_turns_content(voice_results["segmented_transcripts"], session_id)

        # 5. Capa de Fusión Multivariable
        consolidated_scores = build_consolidated_report(voice_results, vision_results, content_results)

        # 6. Generación Narrativa Ejecutiva VISUM (Llamada 2 a LLM)
        cursor.execute("""
            SELECT s.title, s.context, t.optics 
            FROM session ses
            JOIN scenario s ON ses.scenario_id = s.id
            JOIN topic t ON s.topic_id = t.id
            WHERE ses.id = ?
        """, session_id)
        scen_row = cursor.fetchone()
        scenario_meta = {"title": scen_row.title, "context": scen_row.context, "optics": scen_row.optics}
        
        visum_narrative = generate_visum_report(scenario_meta, consolidated_scores)

        # 7. Persistencia Atómica en Azure SQL (report, area_score, analysis_pipeline_result)
        persist_results(cursor, session_id, job_id, rubric_version_id, consolidated_scores, visum_narrative)
        db_conn.commit()
        logger.info(f"Pipeline completado exitosamente para sesión {session_id}")

    except Exception as ex:
        db_conn.rollback()
        logger.error(f"Fallo en pipeline de sesión {session_id}: {str(ex)}")
        cursor.execute("UPDATE analysis_job SET status = 'failed', failure_reason = ? WHERE id = ?", (str(ex)[:500], job_id))
        cursor.execute("UPDATE session SET status = 'failed' WHERE id = ?", session_id)
        db_conn.commit()
    finally:
        cursor.close()
        db_conn.close()
        if os.path.exists(local_video_path):
            os.remove(local_video_path)

```

### MÓDULO 3: COMANDOS DE DESPLIEGUE Y CONFIGURACIÓN EN AZURE

Ejecutar estos comandos en Git Bash para aplicar la configuración en la infraestructura activa:

```bash
export SUBSCRIPTION_NAME="Azure for Students"
export RG_NAME="rg-voxready-dev"
export ACR_NAME="crvoxreadyst"
export WORKER_APP_NAME="ca-analysis-worker"
export SQL_SERVER_NAME="sql-voxready-st"
export SQL_DB_NAME="sqldb-voxready"

az account set --subscription "$SUBSCRIPTION_NAME"

# 1. Compilar y subir la nueva imagen del Worker con Uvicorn
cd voxready-worker
az acr build --registry "$ACR_NAME" --image analysis-worker:v2.2 .
cd ..

# 2. Actualizar ca-analysis-worker a Ingress Interno y Escala a Cero
az containerapp update \
  --name "$WORKER_APP_NAME" \
  --resource-group "$RG_NAME" \
  --image "$ACR_NAME.azurecr.io/analysis-worker:v2.2" \
  --ingress internal \
  --target-port 8000 \
  --min-replicas 0 \
  --max-replicas 1

# 3. Configurar Auto-Pausa a 60 minutos en Azure SQL para detener consumo inactivo
az sql db update \
  --resource-group "$RG_NAME" \
  --server "$SQL_SERVER_NAME" \
  --name "$SQL_DB_NAME" \
  --auto-pause-delay 60 \
  --min-capacity 0.5

```
