### FASE 0: PRE-FLIGHT CHECKS Y AUTENTICACIÓN

```bash
# 1. Asegurar suscripción activa
az account set --subscription "$SUBSCRIPTION_NAME"

# Verificación de contexto
ACTIVE_SUB=$(az account show --query "name" -o tsv)
if [ "$ACTIVE_SUB" != "$SUBSCRIPTION_NAME" ]; then
  echo "Error: Suscripción activa no coincide con $SUBSCRIPTION_NAME" >&2
  exit 1
fi

# 2. Login en Docker contra el nuevo ACR
ACR_PASS=$(az acr credential show --name "$ACR_NAME" --query "passwords[0].value" -o tsv)
echo "$ACR_PASS" | docker login "$ACR_NAME.azurecr.io" -u "$ACR_NAME" --password-stdin

# 3. Validar existencia de secretos críticos en Key Vault
for SECRET in "SQL-CONNECTION-STRING" "STORAGE-CONNECTION-STRING" "SERVICE-BUS-CONNECTION-STRING" "NVIDIA-API-KEY"; do
  EXISTS=$(az keyvault secret list --vault-name "$KV_NAME" --query "[?name=='$SECRET'].name" -o tsv)
  if [ -z "$EXISTS" ]; then
    echo "Falta el secreto $SECRET en $KV_NAME" >&2
    exit 1
  fi
done

```

### FASE 1: COMPILACIÓN LOCAL Y DESPLIEGUE DE MICROSERVICIOS

#### 1.1 Microservicio de Visión (`ca-vision-service`)

*Especificación:* Escalado estricto a 0 réplicas, Ingress interno en puerto 8000, 0.5 CPU, 1.0 GiB.

```bash
cd voxready-vision
docker build --platform linux/amd64 -t "$ACR_NAME.azurecr.io/vision-service:v1" .
docker push "$ACR_NAME.azurecr.io/vision-service:v1"
cd ..

az containerapp create \
  --name ca-vision-service \
  --resource-group "$RG_NAME" \
  --environment "$ENVIRONMENT_NAME" \
  --image "$ACR_NAME.azurecr.io/vision-service:v1" \
  --registry-server "$ACR_NAME.azurecr.io" \
  --registry-username "$ACR_NAME" \
  --registry-password "$ACR_PASS" \
  --target-port 8000 \
  --ingress internal \
  --cpu 0.5 \
  --memory 1.0Gi \
  --min-replicas 0 \
  --max-replicas 2

# Guardar URL interna en Key Vault
VISION_FQDN=$(az containerapp show --name ca-vision-service --resource-group "$RG_NAME" --query "properties.configuration.ingress.fqdn" -o tsv)
az keyvault secret set --vault-name "$KV_NAME" --name "VISION-SERVICE-URL" --value "https://$VISION_FQDN"

```

#### 1.2 Microservicio API Backend (`ca-backend-api`)

*Especificación:* Ingress externo en puerto 8000, validación de JWT, resolución de credenciales desde Key Vault.

```bash
cd voxready-backend
docker build --platform linux/amd64 -t "$ACR_NAME.azurecr.io/backend-api:v1" .
docker push "$ACR_NAME.azurecr.io/backend-api:v1"
cd ..

SQL_CONN=$(az keyvault secret show --vault-name "$KV_NAME" --name "SQL-CONNECTION-STRING" --query "value" -o tsv)
STORAGE_CONN=$(az keyvault secret show --vault-name "$KV_NAME" --name "STORAGE-CONNECTION-STRING" --query "value" -o tsv)
SB_CONN=$(az keyvault secret show --vault-name "$KV_NAME" --name "SERVICE-BUS-CONNECTION-STRING" --query "value" -o tsv)

az containerapp create \
  --name ca-backend-api \
  --resource-group "$RG_NAME" \
  --environment "$ENVIRONMENT_NAME" \
  --image "$ACR_NAME.azurecr.io/backend-api:v1" \
  --registry-server "$ACR_NAME.azurecr.io" \
  --registry-username "$ACR_NAME" \
  --registry-password "$ACR_PASS" \
  --target-port 8000 \
  --ingress external \
  --cpu 0.5 \
  --memory 1.0Gi \
  --min-replicas 0 \
  --max-replicas 2 \
  --secrets \
    sql-conn="$SQL_CONN" \
    storage-conn="$STORAGE_CONN" \
    sb-conn="$SB_CONN" \
  --env-vars \
    SQL_CONNECTION_STRING=secretref:sql-conn \
    STORAGE_CONNECTION_STRING=secretref:storage-conn \
    SERVICE_BUS_CONNECTION_STRING=secretref:sb-conn \
    SERVICE_BUS_QUEUE_NAME="analysis-queue" \
    STORAGE_CONTAINER_NAME="recordings"

BACKEND_FQDN=$(az containerapp show --name ca-backend-api --resource-group "$RG_NAME" --query "properties.configuration.ingress.fqdn" -o tsv)
az keyvault secret set --vault-name "$KV_NAME" --name "BACKEND-API-URL" --value "https://$BACKEND_FQDN"

```

#### 1.3 Microservicio Worker de Análisis (`ca-analysis-worker`)

*Especificación:* Sin Ingress, KEDA trigger contra Service Bus (`analysis-queue`), FFmpeg, Parakeet y Llama 3.2 90B.

```bash
cd voxready-worker
docker build --platform linux/amd64 -t "$ACR_NAME.azurecr.io/analysis-worker:v1" .
docker push "$ACR_NAME.azurecr.io/analysis-worker:v1"
cd ..

NVIDIA_KEY=$(az keyvault secret show --vault-name "$KV_NAME" --name "NVIDIA-API-KEY" --query "value" -o tsv)
VISION_URL=$(az keyvault secret show --vault-name "$KV_NAME" --name "VISION-SERVICE-URL" --query "value" -o tsv)

az containerapp create \
  --name ca-analysis-worker \
  --resource-group "$RG_NAME" \
  --environment "$ENVIRONMENT_NAME" \
  --image "$ACR_NAME.azurecr.io/analysis-worker:v1" \
  --registry-server "$ACR_NAME.azurecr.io" \
  --registry-username "$ACR_NAME" \
  --registry-password "$ACR_PASS" \
  --cpu 1.0 \
  --memory 2.0Gi \
  --min-replicas 0 \
  --max-replicas 2 \
  --secrets \
    sb-conn="$SB_CONN" \
    storage-conn="$STORAGE_CONN" \
    sql-conn="$SQL_CONN" \
    nvidia-key="$NVIDIA_KEY" \
  --env-vars \
    SERVICE_BUS_CONNECTION_STRING=secretref:sb-conn \
    STORAGE_CONNECTION_STRING=secretref:storage-conn \
    SQL_CONNECTION_STRING=secretref:sql-conn \
    NVIDIA_API_KEY=secretref:nvidia-key \
    NVIDIA_BASE_URL="https://integrate.api.nvidia.com/v1" \
    LLM_MODEL_NAME="meta/llama-3.2-90b-vision-instruct" \
    VISION_SERVICE_URL="$VISION_URL" \
    SERVICE_BUS_QUEUE_NAME="analysis-queue" \
    STORAGE_CONTAINER_NAME="recordings" \
  --scale-rule-name servicebus-queue-rule \
  --scale-rule-type azure-servicebus \
  --scale-rule-metadata queueName=analysis-queue messageCount=1 \
  --scale-rule-auth connection=sb-conn

```

### FASE 4: MATRIZ DE VERIFICACIONES POST-DEPLOY (SMOKE TESTS)

Antigravity debe ejecutar la siguiente batería de comprobaciones lógicas:

#### Verificación 1: Salud de la API y Documentación OpenAPI

```bash
HTTP_STATUS=$(curl -s -o /dev/null -w "%{http_code}" "https://$BACKEND_FQDN/docs")
if [ "$HTTP_STATUS" -ne 200 ]; then
  echo "Fallo de salud en Backend API: Código HTTP $HTTP_STATUS" >&2
  exit 1
fi
echo "✔ Backend API respondiendo HTTP 200 OK en Swagger."

```

#### Verificación 2: Persistencia y Consulta DDL en Azure SQL

Consultar si el usuario seed y la rúbrica existen en la base de datos `sqldb-voxready`:

```bash
python -c "
import pyodbc, os
conn_str = '''$SQL_CONN'''
conn = pyodbc.connect(conn_str)
cursor = conn.cursor()
cursor.execute('SELECT COUNT(*) FROM rubric_version WHERE status = \'published\';')
count = cursor.fetchone()[0]
assert count >= 1, 'Rúbrica no inicializada'
print('✔ Base de datos verificada con ' + str(count) + ' versión(es) de rúbrica activa(s).')
"

```

#### Verificación 3: Validación del Endpoint OIDC de CIAM

Verificar la resolución del Discovery Document de Microsoft Entra External ID:

```bash
OIDC_ISSUER=$(curl -s "https://voxreadydev.ciamlogin.com/$CIAM_TENANT_ID/v2.0/.well-known/openid-configuration" | jq -r '.issuer')
if [[ "$OIDC_ISSUER" != *"$CIAM_TENANT_ID"* ]]; then
  echo "Fallo de resolución OIDC en CIAM" >&2
  exit 1
fi
echo "✔ Endpoint CIAM OIDC operativo: $OIDC_ISSUER"

```

#### Verificación 4: Estado de Réplicas en Reposo (Zero-Idle Cost)

Comprobar que los tres servicios admitan escalado a cero y no incurran en consumo continuo de vCPU:

```bash
for APP in ca-vision-service ca-backend-api ca-analysis-worker; do
  MIN_REP=$(az containerapp show --name "$APP" --resource-group "$RG_NAME" --query "properties.template.scale.minReplicas" -o tsv)
  if [ "$MIN_REP" -ne 0 ]; then
    echo "Advertencia: $APP tiene minReplicas en $MIN_REP (debería ser 0)" >&2
  else
    echo "✔ $APP configurado para escalar a 0 réplicas."
  fi
done

```

#### Verificación 5: Ciclo de Emisión SAS (Blob Direct-to-Storage)

Probar la emisión del token de carga temporal sin transferir binarios por la API:

```bash
TEST_SAS=$(az storage container generate-sas \
  --account-name "$STORAGE_NAME" \
  --name "recordings" \
  --permissions w \
  --expiry $(date -u -d "30 minutes" '+%Y-%m-%dT%H:%MZ') \
  --auth-mode key \
  -o tsv)

if [ -z "$TEST_SAS" ]; then
  echo "Fallo al generar URL SAS en $STORAGE_NAME" >&2
  exit 1
fi
echo "✔ Mecanismo SAS Storage validado correctamente."

```
