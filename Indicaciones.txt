# AGENT DIRECTIVE: Extracción Automatizada de Variables por Azure CLI y Sincronización de Entornos (.env)

## 1. Contexto Operacional y Parámetros Base

Este procedimiento instruye al agente de automatización a extraer dinámicamente mediante Azure CLI (`az`) todos los identificadores, secretos, URLs y cadenas de conexión aprovisionados en el grupo `rg-voxready-dev` (región `westus`) para generar o sustituir de forma atómica los archivos de entorno locales:

* `voxready-backend/.env`
* `voxready-worker/.env`
* `voxready-frontend/.env.local`

### Parámetros de Infraestructura Objetivo

* **Resource Group:** `rg-voxready-dev`
* **Key Vault:** `kv-voxready-st`
* **Storage Account:** `stavoxreadyst` (Contenedor: `recordings`)
* **Service Bus Namespace:** `sb-voxready-st` (Cola: `analysis-queue`)
* **SQL Server:** `sql-voxready-st` (BD: `sqldb-voxready`)
* **Container Apps:** `ca-vision-service`, `ca-backend-api`

---

## 2. Matriz de Extracción CLI

| Variable destino | Archivo (.env) | Origen / Comando Azure CLI |
| --- | --- | --- |
| `SQL_CONNECTION_STRING` | Backend, Worker | `az keyvault secret show --vault-name kv-voxready-st --name "SQL-CONNECTION-STRING" --query "value" -o tsv` |
| `STORAGE_CONNECTION_STRING` | Backend, Worker | `az storage account show-connection-string --name stavoxreadyst --resource-group rg-voxready-dev --query "connectionString" -o tsv` |
| `SERVICE_BUS_CONNECTION_STRING` | Backend, Worker | `az servicebus namespace authorization-rule keys list --resource-group rg-voxready-dev --namespace-name sb-voxready-st --name RootManageSharedAccessKey --query "primaryConnectionString" -o tsv` |
| `VISION_SERVICE_URL` | Worker | `https://$(az containerapp show --name ca-vision-service --resource-group rg-voxready-dev --query "properties.configuration.ingress.fqdn" -o tsv)` |
| `NVIDIA_API_KEY` | Worker | `az keyvault secret show --vault-name kv-voxready-st --name "NVIDIA-API-KEY" --query "value" -o tsv` |
| `NEXT_PUBLIC_API_URL` | Frontend | `https://$(az containerapp show --name ca-backend-api --resource-group rg-voxready-dev --query "properties.configuration.ingress.fqdn" -o tsv)/v1` |
| `NEXT_PUBLIC_AZURE_TENANT_ID` | Frontend | `az account show --query "tenantId" -o tsv` |
| `NEXT_PUBLIC_AZURE_CLIENT_ID` | Frontend | Extraído de Entra ID o recuperado desde `kv-voxready-st` (secreto `ENTRA-CLIENT-ID`) |

---

## 3. Script de Automatización: `sync-env.sh`

El agente debe ejecutar este script desde la raíz del repositorio (`voxready/`). El script consulta los servicios en Azure, valida que los valores no sean nulos y sobrescribe los archivos `.env` respectivos.

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "==> [1/4] Verificando contexto de suscripción..."
CURRENT_SUB=$(az account show --query "name" -o tsv)
echo "Suscripción activa: $CURRENT_SUB"

RG_NAME="rg-voxready-dev"
KV_NAME="kv-voxready-st"
STORAGE_NAME="stavoxreadyst"
SB_NAME="sb-voxready-st"

echo "==> [2/4] Consultando Azure CLI y Azure Key Vault..."

# 1. Cadenas de conexión compartidas
echo "Consultando conexión a Storage..."
STORAGE_CONN=$(az storage account show-connection-string \
  --name "$STORAGE_NAME" \
  --resource-group "$RG_NAME" \
  --query "connectionString" -o tsv)

echo "Consultando conexión a Service Bus..."
SB_CONN=$(az servicebus namespace authorization-rule keys list \
  --resource-group "$RG_NAME" \
  --namespace-name "$SB_NAME" \
  --name RootManageSharedAccessKey \
  --query "primaryConnectionString" -o tsv)

echo "Consultando conexión a Azure SQL desde Key Vault..."
SQL_CONN=$(az keyvault secret show \
  --vault-name "$KV_NAME" \
  --name "SQL-CONNECTION-STRING" \
  --query "value" -o tsv || echo "")

# 2. Secretos y credenciales de IA
echo "Consultando NVIDIA API Key desde Key Vault..."
NVIDIA_KEY=$(az keyvault secret show \
  --vault-name "$KV_NAME" \
  --name "NVIDIA-API-KEY" \
  --query "value" -o tsv || echo "")

# 3. FQDNs de Azure Container Apps
echo "Consultando FQDN de ca-vision-service..."
VISION_FQDN=$(az containerapp show \
  --name ca-vision-service \
  --resource-group "$RG_NAME" \
  --query "properties.configuration.ingress.fqdn" -o tsv || echo "")

echo "Consultando FQDN de ca-backend-api..."
BACKEND_FQDN=$(az containerapp show \
  --name ca-backend-api \
  --resource-group "$RG_NAME" \
  --query "properties.configuration.ingress.fqdn" -o tsv || echo "")

# 4. Parámetros de Tenant y Auth
TENANT_ID=$(az account show --query "tenantId" -o tsv)

# Intentar extraer Client ID de Entra ID registrado para VoxReady (o consultar Key Vault)
CLIENT_APP_ID=$(az ad app list --display-name "voxready" --query "[0].appId" -o tsv 2>/dev/null || echo "")
if [ -z "$CLIENT_APP_ID" ]; then
  CLIENT_APP_ID=$(az keyvault secret show --vault-name "$KV_NAME" --name "ENTRA-CLIENT-ID" --query "value" -o tsv 2>/dev/null || echo "PENDIENTE_DE_CONFIGURAR")
fi

echo "==> [3/4] Generando archivos .env..."

# -------------------------------------------------------------
# A. voxready-backend/.env
# -------------------------------------------------------------
mkdir -p voxready-backend
cat <<EOF > voxready-backend/.env
# Generado automáticamente por CLI Sync
SQL_CONNECTION_STRING="${SQL_CONN}"
STORAGE_CONNECTION_STRING="${STORAGE_CONN}"
STORAGE_CONTAINER_NAME="recordings"
SERVICE_BUS_CONNECTION_STRING="${SB_CONN}"
SERVICE_BUS_QUEUE_NAME="analysis-queue"
EOF
echo "✔ voxready-backend/.env generado exitosamente."

# -------------------------------------------------------------
# B. voxready-worker/.env
# -------------------------------------------------------------
mkdir -p voxready-worker
cat <<EOF > voxready-worker/.env
# Generado automáticamente por CLI Sync
SQL_CONNECTION_STRING="${SQL_CONN}"
STORAGE_CONNECTION_STRING="${STORAGE_CONN}"
STORAGE_CONTAINER_NAME="recordings"
SERVICE_BUS_CONNECTION_STRING="${SB_CONN}"
SERVICE_BUS_QUEUE_NAME="analysis-queue"

# Pipeline de Visión y Modelos Externos
VISION_SERVICE_URL="https://${VISION_FQDN}"
NVIDIA_API_KEY="${NVIDIA_KEY}"
NVIDIA_BASE_URL="https://integrate.api.nvidia.com/v1"
LLM_MODEL_NAME="meta/llama-3.2-90b-vision-instruct"
EOF
echo "✔ voxready-worker/.env generado exitosamente."

# -------------------------------------------------------------
# C. voxready-frontend/.env.local
# -------------------------------------------------------------
mkdir -p voxready-frontend
cat <<EOF > voxready-frontend/.env.local
# Generado automáticamente por CLI Sync
NEXT_PUBLIC_API_URL="https://${BACKEND_FQDN}/v1"
NEXT_PUBLIC_AZURE_CLIENT_ID="${CLIENT_APP_ID}"
NEXT_PUBLIC_AZURE_TENANT_ID="${TENANT_ID}"
NEXT_PUBLIC_REDIRECT_URI="http://localhost:3000"
EOF
echo "✔ voxready-frontend/.env.local generado exitosamente."

echo "==> [4/4] Sincronización completada."

```

## 4. Instrucciones de Ejecución para Antigravity

1. **Permisos de Ejecución:**
Guardar el contenido en `scripts/sync-env.sh` y otorgar permisos de ejecución:
```bash
chmod +x scripts/sync-env.sh
./scripts/sync-env.sh

```


2. **Orden de Dependencia Obligatorio:**
* Las Container Apps (`ca-vision-service` y `ca-backend-api`) deben haber sido aprovisionadas previamente para que `az containerapp show` retorne los FQDNs válidos de `westus`.
* Si las Container Apps aún no se han desplegado, el script insertará temporalmente cadenas vacías en `VISION_SERVICE_URL` y `NEXT_PUBLIC_API_URL`, requiriendo una reejecución tras el despliegue del Paso 4.


3. **Validación de Resultados:**
Comprobar que ningún archivo contenga valores vacíos en las variables críticas:
```bash
grep -E "ConnectionString|NEXT_PUBLIC_API_URL|VISION_SERVICE_URL" voxready-*/*env*

```
